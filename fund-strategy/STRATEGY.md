## 二、仓位管理（硬性规则，无条件遵守）

假设总资金 = 100%（以 10 万元为例，1 份 = 1 万元 = 10%）。

1. **单只 ETF 仓位上限 = 15%**（即 1.5 份，任何一只不得超过）。
2. **总仓位上限 = 90%，现金永远 ≥ 10%**（留足子弹，永不满仓）。
3. **单只 ETF 内部结构**：底仓 60% + 网格仓 40%
   - 例：某 ETF 计划配 15% → 底仓 9%（趋势持有）+ 网格仓 6%（高抛低吸）。
4. **每次操作只动 1 份（≤10%）**，严禁一次梭哈。
5. 同时持仓 ETF 数量 ≤ 5 只（分散但不散乱）。

## 三、趋势判断（每天开盘前 3 分钟看完）

用 **MA20 与 MA60** 判断每只 ETF 处于什么状态：

| 状态 | 条件 | 操作基调 |
|------|------|----------|
| 🟢 多头 | 价格 > MA20 > MA60，且 MA20 向上 | 持有底仓，回调加仓 |
| 🟡 震荡 | 价格在 MA20 上下穿梭，MA20 走平 | 只做网格，不加底仓 |
| 🔴 空头 | 价格 < MA20 < MA60，或 MA20 向下 | 减仓/清仓，暂停网格 |

**辅助确认（不单独使用）：**
- MACD（12,26,9）：金叉偏多、死叉偏空；柱体由负转正 = 转强信号。
- RSI（14）：>70 超买（注意减仓），<30 超卖（关注买入）。
- 布林带（20,2）：触下轨 = 买入区，触上轨 = 卖出区。

## 四、网格交易规则（降低成本，辅助收益）

网格只在 **多头/震荡** 状态下运行；空头状态一律暂停网格（防止接飞刀）。

**每只 ETF 的网格设置（以 6% 网格仓为例，拆 3 格，每格 2%）：**

| 触发 | 动作 |
|------|------|
| 价格 ≤ 建仓价 − 3%（第1格） | 买入 1 格（2%） |
| 价格 ≤ 建仓价 − 6%（第2格） | 买入 1 格（2%） |
| 价格 ≤ 建仓价 − 9%（第3格，最多） | 买入 1 格（2%，网格仓用尽） |
| 价格 ≥ 买入均价 + 4% | 卖出 1 格（对应格数） |
| 价格 ≥ 买入均价 + 8% | 卖出 1 格（对应格数） |

> 网格间距可按波动率微调：波动大的（科创50/恒生科技/纳指）间距放宽到 4-5%；波动小的（国债/沪深300）收紧到 2-3%。

## 五、加仓 / 减仓规则（趋势部分）

### 🟢 加仓区（分批买入）
满足 **任意 2 条** 才加 1 份：
1. 多头状态，价格回踩 MA20 且 **RSI < 45**；
2. 价格触及布林下轨且 **RSI < 30**（超卖买点，可加 2 份）；
3. MACD 在零轴上方金叉；
4. 放量上涨突破 20 日新高（突破买点）。

### 🔴 减仓区（分批止盈）
满足 **任意 1 条** 就减 1 份：
1. 价格触及布林上轨且 **RSI > 70**（超卖卖点，减 1 份）；
2. MACD 顶背离（价新高、MACD 不新高）；
3. 跌破 MA20 且 MACD 死叉 → 减至半仓；
4. 单笔盈利 ≥ 12% → 至少减半锁定利润。

### ⚪ 观望区
- 空头状态刚形成（等企稳，不猜底）；
- 单日振幅 > 5%（波动过大，不追）；
- 无趋势（MA20 走平、缩量横盘）。

## 六、风控（止损 + 回撤，保命条款）

### 单笔止损
| 情况 | 动作 |
|------|------|
| 网格单买入后跌超 5% | 该格止损离场 |
| 趋势单买入后跌超 8% | 无条件止损 |
| 收盘跌破 MA60 | 次日开盘清仓该 ETF（趋势彻底走坏） |

### 账户级回撤控制（盯总资产）
| 总资产从最高点回撤 | 动作 |
|------|------|
| ≥ 8% | 总仓位降至 50%，停止开新仓 |
| ≥ 12% | 总仓位降至 30%，只留最强势 1-2 只 |
| ≥ 15% | 全部清仓转现金，休整 ≥ 5 个交易日再战 |

### 纪律红线
- ❌ 永不满仓（现金 ≥ 10%）；
- ❌ 单只 ETF 永不超 15%；
- ❌ 不在亏损单上加仓摊薄；
- ❌ 连续 2 次止损后，强制休息 3 个交易日。

## 七、每日 ETF 精选（Top 3 打分模型）

对池内 25 只 ETF 打分（满分 10 分），选 Top 3：

| 维度 | 分值 | 规则 |
|------|:----:|------|
| 趋势 | 3 分 | MA20>MA60 +1.5；价>MA20 +0.75；MA20 向上 +0.75 |
| 相对动量 | 3 分 | 5日涨幅池内排名百分位 ×1.5 + 20日涨幅池内排名百分位 ×1.5（谁当下更强谁得分高，随市场轮动） |
| 位置 | 2 分 | 布林下轨附近（买点区）+2；中轨附近 +1；上轨附近（已高）0 |
| 新鲜信号 | 2 分 | 近3日 MACD 金叉 +1；放量突破 20 日新高 +1（缩量突破 +0.5）；RSI 上穿 50 +0.5 |
| 加分 | — | 放量（量>5日均量1.5倍）且上涨 +0.5；跌破 MA60 −2 直接出局 |

**Top 3 选择规则（解决固定不变问题）：**
1. 按得分降序排序；
2. 类别分散：每类资产最多选 1 只（宽基/成长/行业/港股/美股/债券/商品），不足 3 只时放宽到每类最多 2 只；
3. 轮换 tie-break：得分相同时，优先选上一期不在 Top3 的新面孔，避免长期霸榜。

**Top 3 只作"重点关注"，是否操作必须再对照第五、六节规则。**

> 报告同时输出全池 25 只打分排名表，Top 3 为市场全景分析的结果，会随强势方向轮动而更换。

## 八、每日执行清单（每天 5 分钟）

1. 看**大盘状态**：510300 的多空 + 池内多头/空头比例（情绪扫描）。
2. 看**Top 3 打分**：找出今日最值得关注的 3 只。
3. 对照**持仓**：检查加仓区/减仓区/观望区，决定今天动哪只、动几份。
4. 检查**风控**：有没有触发止损？账户回撤到哪一档？
5. 执行后记一笔：操作记录写入 `etf-strategy/trades.log`。

### 标的池：25 只核心 + 全市场自动优选（默认合计 60 只）

本策略第一章列出的 **25 只是核心池，固定保底**。在此基础上，`etf_dashboard.py`
会从全市场自动补充到目标只数（默认 60，可用 `--pool-size` 调整）：

| 步骤 | 规则 |
|------|------|
| 1. 拉清单 | 新浪全市场 ETF（按成交额降序），东财接口作为备用源 |
| 2. 剔除 | 货币/现金/短融/同业存单类、债券类| 2. 剔除 | 货币/现金/短融/同业存单类、债券类 —— 日内套利品、低波动品种不适合本策略 |
| 3. 同名去重 | 去掉基金公司后缀与 ETF/基金词缀后同名者，只保留成交额最大的一只 |
| 4. 相关性去重 | 抓出近 60 日收益率，**相关性 > 0.98 视为同一条曲线**，只保留排在前的一只 |
| 5. 截断 | 按上述步骤从成交额排名依次纳入，直到达到目标只数 |

> 核心池永远保底，不受去重影响；`--core-only` 可退回只用第一章的 25 只。

**页面里的价位是怎么来的：**

| 字段 | 计算口径 |
|------|----------|
| 建议买入区间 | 多头：`MA20 × 0.985 ~ MA20 × 1.010`（回踩 MA20 分批接）；其余：布林下轨 ~ 中轨 × 1.005 |
| 目标位 | 保守 = max(布林上轨, 现价 × 1.05)；激进 = max(20 日最高 × 1.02, 保守目标 × 1.03) |
| 止损位 | `min(MA60 × 0.995, 现价 × 0.92)`（趋势单 -8% 铁律，MA60 更低则用 MA60） |
| 仓位建议 | 单只上限 15%：多头高分 = 底仓 9% + 网格 6%；多头一般 = 6% + 4%；震荡 = 网格 6%（3 格 × 2%）；空头 = 0（观望） |
| 网格挂单价 | 以现价为基准 `-3% / -6% / -9%` 三格，每格 = 网格仓 ÷ 3，卖出按买入均价 `+4% / +8%` 了结 |

### 实时性与流量控制（面向服务器部署）

- **登录成功后**才开始拉行情，登录页阶段零外部请求；页面本身单文件、无任何 CDN 依赖。
- **每 30 秒一次**：间隔写在 `#codes` 的 `data-interval` 上，改 Python 侧的 `REFRESH_SECONDS` 即可调整。
- **页面不可见 → 暂停**（`visibilitychange`），切回来先立即补拉一次再恢复节奏。
- **离开页面 → 停止**（`pagehide` / `beforeunload` 双保险），定时器一律清掉。
- 单飞保护：上一轮没回来就不发下一轮；右上角「锁定」按钮可手动停刷新并回到登录页。
- 状态栏显示累计「已拉取 N 次 / 约 X KB」。
- 行情链路是**浏览器直连腾讯**，不经服务器；若要改成服务端代理，上述策略同样适用。

### 访问安全（密码门禁）

- **前置密码登录**：页面正文用 **PBKDF2-SHA256（15 万次迭代）+ SHA256-CTR 流密钥**整体加密，
  浏览器原生 WebCrypto 解密（不可用时自动切换到内置纯 JS 实现）。文件本体内容是密文，
  **不看源码的情况下无法还原**。口令保存在 `dashboard/.secret.json`（已 gitignore），
  `--set-password` 修改、`--no-auth` 生成明文版。
- **部署注意**：页面可通过任意静态服务器发布，单文件无依赖；若后续改为 HTTPS 域名访问更稳妥
  （WebCrypto 在 http 非 localhost 场景下不可用，此时会自动走纯 JS 兜底，功能不受影响）。
